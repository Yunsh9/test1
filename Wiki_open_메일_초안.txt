제목:[검토 요청] 규제Wiki 사내 오픈 방안

1. 목표
- 사내 EIP 퀵링크에 규제 Wiki 링크 등록합니다.
- 사용자가 Snowflake 로그인 없이 링크만 눌러 바로 접속할 수 있게 서비스를 오픈합니다.

2. 검토 결과 요약
- 규제Wiki를 별도의 앱으로 띄워야 합니다.
- Snowflake App Runtime 앱은 접속할 때 반드시 로그인이 필요합니다. 링크만으로는 접근 불가능합니다.
- 그래서 사내 리버스 프록시가 서비스 계정으로 대신 인증하고, 직원은 프록시 주소로 접근하는 방식을 검토했습니다.

3. 목표 아키텍처
[사진 첨부]
1. 사용자가 EIP에 접속합니다. (eip.ktng.com)
2. 퀵링크에서 규제Wiki 링크를 클릭합니다.(ex.regwiki.ktng.com)
3. 요청이 사내 리버스 프록시에 도착합니다.
4. 프록시가 서비스 계정의 개인키로 서명해 Snowflake에서 접속용 토큰을 받습니다.(토큰은 주기적으로 갱신됩니다)
5. 프록시가 요청에 토큰(Authorization 헤더)을 붙여 Snowflake의 규제Wiki 앱으로 전달합니다.
6. 앱이 화면과 데이터를 응답합니다.
7. 프록시가 응답을 직원 브라우저로 전달합니다. (키와 토큰은 직원 PC에 전달하지 않습니다.)

4. 리버스 프록시 구성
- 역할: 서비스 계정 1개로 모든 직원 요청을 대신 인증해 전달합니다. 
- 구현 방식(둘 중 택일)
	1. 기존 nginx, F5, API Gateway에 토큰 발급 스크립트를 추가합니다.(nginx njs 0.8.1 이상 필요, 스크립트 개발 필요)
	2. 외부 패키지 없이 Node 기반 소형 중계 프로그램을 별도로 실행합니다.(프로그램 개발 필요)
- 키와 토큰(키페어 방식)
	- 개인키는 프록시 서버에 보관하고, 공개키는 Snowflake 서비스 계정에 등록합니다.
	- 토큰은 주기적으로 자동 갱신합니다.
- 서비스 계정 권한
	- 서비스 전용 최소 권한 역할 + 규제Wiki 앱 사용 권한만 부여합니다.
	- 테이블 직접 조회나 변경, 다른 앱, DB접근은 불가합니다.
	- Snowflake 네트워크 정책으로 프록시 서버의 사내 IP에서만 이 계정을 쓸 수 있도록 제한합니다.

5. 보안, 부하, 장단점
- 보안
	- 권한이 최소한으로 제한되고 읽기 전용이라 프록시로 할 수 있는 일은 Wiki 조회뿐입니다.
	- 만약 프록시에 있는 개인키가 유출되더라도 네트워크 정책 때문에 외부에서는 사용할 수 없습니다.
	- 프록시 주소가 사내 도메인이라 사내망 안에서만 열립니다.
- 부하
	- 연산이 거의 없는 프로세스 1개입니다. 기존 시스템에서 사용해도 될 것 같습니다.(확인필요)
	- 정확한 CPU와 메모리 사용량은 측정하지 못했습니다.
- 장점
	- 필요한 자원이 프록시뿐입니다.
	- Wiki 앱은 Snowflake 컴퓨팅으로 작동합니다.
- 유의 사항
	- 리버스 프록시가 작동할 곳이 필요합니다.
	- Snowflake에는 모든 접속이 서비스 계정 1개로 기록되어 개별 모니터링은 불가능합니다.
	- 사내 SSL 인스펙션 대응이 필요합니다. 프록시가 사내 인증서를 신뢰하도록 설정하거나, 보안팀에 Snowflake 주소를 검사 대상에서 제외해 달라고 요청해야 합니다.
	
6. 로컬 테스트 결과
- 제 로컬 PC에서 프록시 구성해 테스트한 결과, Wiki 화면과 원본 PDF 열람까지 작동했습니다.
- 다만 개인 PC에서 테스트한 결과이므로 실제 사내에서 동작 여부와 안정성을 확인하는 테스트가 필요해 보입니다.

7. 확인 필요한 사항
- 프록시를 올릴 서버가 있는지, 기존 nginx, F5, API Gateway 활용 가능한지 확인 필요합니다.
- 규제Wiki로 사용할 수 있는 사내 도메인이 있는지 확인 필요합니다.
- SSL 인스펙션 대응 방법을 정해야 합니다. 프록시에 사내 인증서를 신뢰시키거나, Snowflake 주소를 검사 대상에서 제외하는 방법이 있습니다.
- Snowflake 네트워크 정책 등록을 위해 프록시 서버의 고정 출발 IP가 필요합니다.
- 서비스 계정의 개인키를 보관해야 하는데 프록시 서버에 파일로 보관이 가능한지, 주기적으로 교체를 해야하는지 확인 필요합니다.
- 등등 확인이 필요한 사항은 별첨 확인필요 HTML 파일을 참고해주세요(암호화 때문에 부득이 HTML로 보내드립니다)
